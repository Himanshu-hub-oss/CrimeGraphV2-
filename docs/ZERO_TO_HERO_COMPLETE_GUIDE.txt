PART 1: PROBLEM STATEMENT — KYUN BANAYA YE PROJECT?
################################################################################

REAL-WORLD PROBLEM:
-------------------
India mein law enforcement agencies (Police, CBI, NIA, Cyber Cell) ke paas 
criminal data MULTIPLE jagah bikhra hua hota hai:

1. FIR Records → Police station ke database mein
2. CDR (Call Detail Records) → Telecom company ke server pe
3. Financial Transactions → Banks aur hawala networks mein
4. Social Media Posts → Twitter, Telegram, Dark Web pe
5. Suspect Profiles → Alag-alag thane ke records mein

PROBLEM: Ek investigating officer ko ye saara data manually connect karna padta 
hai. Agar koi criminal SUS0024 (Suresh Shah) hai aur wo SUS0104 se secretly 
connected hai through 3 intermediaries, toh manually ye pata lagana IMPOSSIBLE 
hai jab 150+ suspects, 2000+ calls, 500+ interactions hain.

MANUAL ANALYSIS KI LIMITATIONS:
- Bahut slow hai (weeks/months lag jaate hain)
- Human error hota hai (connections miss ho jaate hain)
- Hidden patterns nahi dikhte (indirect criminal links)
- Evidence tamper ho sakta hai (digital records change kar sakte hain)
- Reactive policing hoti hai (crime hone ke BAAD action)

HAMARA SOLUTION — CRIMEGRAPH AI:
- AI se automatically criminal networks ko MAP karo
- ML models se PREDICT karo kaun high risk hai
- Graph analytics se HIDDEN connections dhundho
- Blockchain se digital evidence TAMPER-PROOF banao
- Dashboard se sab kuch EK JAGAH dekhoo

PART 5: src/graph_engine.py — GRAPH ANALYTICS ENGINE
################################################################################

FILE: src/graph_engine.py (400 lines)
CLASS: CriminalGraphEngine
LIBRARY: NetworkX (Python ka graph analysis library)

YE KYA KARTA HAI:
Ye class criminal suspect network ko ek MATHEMATICAL GRAPH mein convert karti hai.
Graph mein:
- NODE = Ek suspect (SUS0001, SUS0002, etc.)
- EDGE = Do suspects ke beech connection (call, financial, co-accused)
- WEIGHT = Connection kitni strong hai

Result: 150 Nodes, 1,567 Edges ka ek complex criminal network

=== STEP 1: build_graph(self) ===

Ye method 4 sources se graph banata hai:

SOURCE 1 — suspects.csv se NODES bante hain:
Har suspect ek node hai jismein attributes hain:
  - name, age, gender, city, gang, role, crime_type, risk_level, phone, prior_cases
Code: self.G.add_node(suspect_id, name=..., age=..., gang=..., ...)

SOURCE 2 — network_edges.csv se DIRECT EDGES bante hain:
Agar SUS0010 aur SUS0045 ka known interaction hai with weight 7.5:
  Edge: SUS0010 ↔ SUS0045, weight=7.5, type="Financial+Call"
Agar pehle se edge hai toh weight ADD ho jaata hai (stronger connection)

SOURCE 3 — fir_records.csv se CO-ACCUSED EDGES bante hain:
Agar FIR mein accused = "SUS0036;SUS0022;SUS0122" hai, toh:
  3 combinations bante hain: 36-22, 36-122, 22-122
  Har pair ke beech weight 2.0 ka edge add hota hai
  Type: "Co-Accused FIR"
YE BAHUT IMPORTANT HAI kyunki ek FIR mein saath hona matlab definitely connected hain!

SOURCE 4 — cdr_records.csv se CALL FREQUENCY EDGES bante hain:
Pehle caller-callee pairs group hote hain, phir call count calculate hota hai.
Agar SUS0034 ne SUS0074 ko 10 baar call kiya:
  Edge weight += 10 * 0.5 = 5.0 add hota hai
  Type: "CDR Call"
0.5 multiplier isliye hai kyunki sirf call karna weak evidence hai compared to
financial transaction ya co-accused hona.


=== STEP 2: compute_all_metrics(self) ===

Graph ban gaya — ab us par ANALYTICS chalte hain. Ye step har node ke liye 
CENTRALITY METRICS calculate karta hai:

METRIC 1 — DEGREE CENTRALITY:
Kitne direct connections hain?
Agar SUS0001 ke 20 connections hain, toh degree = 20.
Simple but important — zyada connections = zyada involved.

METRIC 2 — BETWEENNESS CENTRALITY (sabse important!):
"Ye suspect kitne SHORTEST PATHS pe baitha hai?"
Imagine karo SUS0003 ke bina, GANG01 aur GANG02 ke beech communication
cut ho jayegi — toh SUS0003 ka betweenness bahut HIGH hoga.
Ye BROKER/GATEKEEPER identify karta hai — jo log information flow control karte hain.
Formula: BC(v) = Sum of (shortest paths through v / total shortest paths)

METRIC 3 — EIGENVECTOR CENTRALITY:
"Kya ye suspect POWERFUL logon se connected hai?"
Agar SUS0005 ke 5 connections hain lekin wo 5 logon mein se 4 Kingpins hain,
toh uska eigenvector bahut HIGH hoga.
Ye "power by association" measure karta hai.

METRIC 4 — PAGERANK:
Google ka algorithm — jo page (suspect) pe zyada important pages (suspects)
point karte hain, wo zyada important hai.
Random walk probability ke basis pe calculate hota hai.

METRIC 5 — CLOSENESS CENTRALITY:
"Ye suspect average mein kitne steps mein sabse baat kar sakta hai?"
Agar SUS0010 ko kisi bhi suspect tak 2-3 steps mein pahunchna hai,
toh wo bahut "close" hai network ke center mein.

METRIC 6 — CLUSTERING COEFFICIENT:
"Ye suspect ke neighbors aapas mein kitne connected hain?"
Agar SUS0010 ke 5 neighbors hain aur wo 5 logon mein se 4 aapas mein bhi
connected hain → clustering coefficient HIGH.
Ye tight-knit criminal cells identify karta hai.

METRIC 7 — COMMUNITY DETECTION (Louvain Algorithm):
Ye poore network ko SUB-GROUPS (communities) mein todta hai.
Louvain algorithm MODULARITY maximize karta hai:
- Same community ke andar zyada edges honi chahiye
- Different communities ke beech kam edges honi chahiye
Result: Har suspect ko ek community_id milta hai (0, 1, 2, 3, ...)
Ye secretly operating sub-gangs ko identify karta hai jo official gang
affiliation se different ho sakte hain.

=== COMPOSITE KINGPIN SCORE (0-100) ===
Sabse important metric — sab ka combination:
kingpin_score = (betweenness * 35)     → 35% weight (broker role)
              + (eigenvector * 35)      → 35% weight (powerful connections)
              + (pagerank * 15)         → 15% weight (importance)
              + (degree/20 * 10)        → 10% weight (connectivity)
              + (prior_cases/6 * 5)     →  5% weight (criminal history)
              * 100 scale

Score 99.9 = Sabse powerful network kingpin
Score 5.0  = Barely connected, low-level operative


=== STEP 3: get_top_kingpins(top_n=15) ===

=== STEP 4: find_shortest_criminal_path(source_id, target_id) ===

Har hop pe connection type aur weight bhi batata hai.

=== STEP 5: get_mutual_accomplices(suspect_a, suspect_b) ===

Ye link prediction mein bhi use hota hai.

PART 6: src/blockchain_engine.py — BLOCKCHAIN EVIDENCE LAYER
################################################################################

FILE: src/blockchain_engine.py (273 lines)
CLASSES: EvidenceBlock, EvidenceBlockchain

YE KYA KARTA HAI:
Digital evidence ko TAMPER-PROOF banata hai using SHA-256 cryptographic hashing.
Court mein evidence tabhi admissible hota hai jab prove ho ki kisi ne modify
nahi kiya — blockchain ye guarantee deta hai.

=== BLOCKCHAIN KAISE KAAM KARTA HAI? (Simple Explanation) ===

Imagine karo ek CHAIN OF BOXES:

Box 0 (Genesis) → Box 1 → Box 2 → Box 3 → Box 4 → Box 5
  |                 |        |        |        |        |
  HASH_0          HASH_1   HASH_2   HASH_3   HASH_4   HASH_5
  |                 |        |        |        |        |
  prev=000...     prev=     prev=    prev=    prev=    prev=
                  HASH_0    HASH_1   HASH_2   HASH_3   HASH_4

Har box mein:
1. Evidence data hai (FIR record, CDR log, social media post, etc.)
2. Evidence ka SHA-256 HASH hai (64-character fingerprint)
3. PREVIOUS BOX ka hash hai
4. Apna BLOCK HASH hai (sab combine karke)

Ab agar koi ATTACKER Box 2 ka data change kare:
- Box 2 ka evidence_hash change ho jayega
- Box 2 ka block_hash change ho jayega
- Lekin Box 3 mein previous_hash = Box 2 ka OLD hash hai
- MISMATCH! → Tampering detected! 

=== CLASS: EvidenceBlock ===

Ek single block represent karta hai:

Fields:
- index          : Block number (0, 1, 2, ...)
- timestamp      : Kab register hua
- evidence_id    : Evidence ka unique ID (EVID_FIR_0001, etc.)
- evidence_type  : Kya type ka evidence hai (FIR Record, CDR Call Log, etc.)
- case_id        : Kis FIR case se related hai
- payload        : ACTUAL EVIDENCE DATA (dict/string)
- officer_badge  : Kis officer ne register kiya
- police_station : Kis police station se
- authorized_role: Kis role ke under registered (Smart Contract check)
- previous_hash  : Previous block ka hash (CHAIN LINK)
- evidence_hash  : Payload ka SHA-256 hash (EVIDENCE FINGERPRINT)
- merkle_root    : Evidence ID + Case ID + Officer + Evidence Hash ka combined hash
- block_hash     : Index + Timestamp + Merkle Root + Previous Hash ka combined hash

HASHING FUNCTIONS:
1. calculate_evidence_hash(payload):
   payload → JSON string → SHA-256 → 64-char hex string
   Example: {"accused": ["SUS0036"]} → "a3f8c2d1e5..."

2. calculate_merkle_root():
   MERKLE TREE banata hai:
                 [Merkle Root]
                /             \
        [Hash(1+2)]         [Evidence Hash]
        /         \
   [Hash(EVID:CASE)]  [Hash(OFFICER:STATION)]
   
   4 leaves combine hokar 1 root banta hai — isse INDIVIDUAL leaf 
   ka tampering bhi detect ho jaata hai.

3. calculate_block_hash():
   f"{index}{timestamp}{merkle_root}{previous_hash}{role}" → SHA-256
   Ye BLOCK SIGNATURE hai — agar kuch bhi change ho, ye change ho jayega.


=== CLASS: EvidenceBlockchain ===

SMART CONTRACT ACCESS CONTROL:
Kaun kya register kar sakta hai — ye rules hain:

ROLE_INVESTIGATING_OFFICER → FIR Record, Arrest Memo, Confession Audio, Seizure Memo
ROLE_CYBER_CELL            → CDR Call Log, Social Media Threat Post, IP Wiretap Dump
ROLE_FORENSIC_EXPERT       → Ballistics Report, Digital Device Clone, DNA Report, Financial Ledger
ROLE_MAGISTRATE_JUDGE      → Judicial Warrant, Court Evidence Seal, Trial Ruling Record

Agar INVESTIGATING_OFFICER CDR Call Log register karne ki koshish kare:
→ Permission mismatch → EMERGENCY_OVERRIDE flag lagta hai (audit trail)

SEEDED BLOCKS (6 blocks initially):
Block 0: Genesis (system root)
Block 1: FIR Evidence — FIR0001 ke accused SUS0036, SUS0022, SUS0122
Block 2: CDR Wiretap — SUS0034 ne SUS0074 ko 266 sec call kiya
Block 3: Social Media Threat — SUS0032 ka Twitter post "Big deal coming"
Block 4: Financial Ledger — SUS0088 se SUS0147 ko 47 lakh transfer
Block 5: Seizure Memo — SUS0115 se 9mm pistol, fake passport, encrypted phone

verify_chain_integrity():
POORA CHAIN traverse karke har block ka:
1. previous_hash check karta hai (kya previous block ka hash match karta hai?)
2. evidence_hash recalculate karta hai (kya payload change hua hai?)
3. block_hash recalculate karta hai (kya block metadata change hua hai?)
Agar koi mismatch → TAMPERED block report karta hai

simulate_tampering_attack(block_index):
DEMO PURPOSE ke liye — ek block ka payload directly modify karta hai
WITHOUT re-mining (hash update nahi karta).
Phir verify_chain_integrity() chalao → wo detect kar lega!

═══════════════════════════════════════════════════
MODEL 2: CRIMINAL LINK PREDICTOR
═══════════════════════════════════════════════════

PURPOSE: Kya do suspects ke beech HIDDEN criminal connection hai?
         Jo abhi graph mein edge nahi hai, kya future mein connection milega?

ALGORITHM: Random Forest Classifier (100 trees, depth 6)

INPUT (8 Features per suspect pair):
┌───────────────────────┬──────────────────────────────────────────────────────┐
│ Feature               │ Kya Measure Karta Hai                                │
├───────────────────────┼──────────────────────────────────────────────────────┤
│ common_neighbors      │ Kitne common contacts hain (Graph topology)          │
│ jaccard_coefficient   │ Common neighbors / Total unique neighbors            │
│ adamic_adar_index     │ Common neighbors weighted by 1/log(degree)           │
│ preferential_attach   │ degree(A) × degree(B) — popular nodes attract        │
│ same_gang             │ Kya dono same gang ke hain? (1 ya 0)                 │
│ same_city             │ Kya dono same city mein hain? (1 ya 0)               │
│ same_crime            │ Kya dono same crime type karte hain? (1 ya 0)        │
│ prior_cases_sum       │ Dono ke prior cases ka total                         │
└───────────────────────┴──────────────────────────────────────────────────────┘

TRAINING DATA KAISE BANTA HAI:
- POSITIVE PAIRS (label=1): network_edges.csv se — ye pairs mein edge hai
  500 pairs jo already connected hain
- NEGATIVE PAIRS (label=0): Randomly chosen pairs jismein NO edge hai
  500 pairs jo connected NAHI hain
- Total: 1000 pairs (balanced dataset)

OUTPUT:
  link_probability: 0.0 to 1.0 (collusion chance)
  threat_status:
    >= 0.70 → "HIGH Criminal Collusion Probability"
    >= 0.40 → "MODERATE Indirect Link Potential"
    < 0.40  → "LOW Probability of Collusion"

RESULT: 90.2% Accuracy

Topology Features Explained:

COMMON NEIGHBORS:
  A — C — B   (C is common neighbor of A and B)
  Agar A aur B ke bahut saare common neighbors hain, toh A-B connected hone
  ki probability HIGH hai.

JACCARD COEFFICIENT:
  |Neighbors(A) ∩ Neighbors(B)| / |Neighbors(A) ∪ Neighbors(B)|
  Ye normalized measure hai — 0 to 1 range mein.

ADAMIC-ADAR INDEX:
  Sum over common neighbors w: 1/log(degree(w))
  Agar common neighbor w ke bahut kam connections hain, toh uska contribution
  ZYADA hota hai (wo specifically A aur B ke beech link hai).
  Agar common neighbor w ke 100 connections hain, toh 1/log(100) = chhota
  (wo sabse connected hai, A-B specific nahi).

PREFERENTIAL ATTACHMENT:
  degree(A) × degree(B)
  Popular nodes ke beech connection hone ki probability zyada hoti hai.
  "Rich get richer" phenomenon.

MODEL 3: NLP SOCIAL MEDIA THREAT CLASSIFIER
═══════════════════════════════════════════════════

PURPOSE: Intercepted social media text se THREAT LEVEL identify karo.
         Kya ye post Neutral hai ya Suspicious ya Threatening ya Coded?

ALGORITHM: TF-IDF Vectorizer + Random Forest (100 trees, depth 8)

TF-IDF KYA HAI? (Text ko Numbers mein Convert Karna)

Step 1 — TOKENIZATION:
  "New shipment arriving from border" → ["new", "shipment", "arriving", "from", "border"]

Step 2 — TF (Term Frequency):
  Har word kitni baar aaya ek document mein
  "shipment" appears 1 time in 5 words → TF = 1/5 = 0.2

Step 3 — IDF (Inverse Document Frequency):
  Agar "shipment" sirf 10/600 posts mein aaya → IDF = log(600/10) = 1.78
  Agar "the" 500/600 posts mein aaya → IDF = log(600/500) = 0.08
  RARE words ko zyada weight milta hai kyunki wo zyada INFORMATIVE hain.

Step 4 — TF-IDF = TF × IDF
  "shipment" → 0.2 × 1.78 = 0.356 (important word!)
  "the"      → 0.2 × 0.08 = 0.016 (not important)

Our Settings:
- ngram_range=(1,2): Unigrams + Bigrams ("shipment", "new shipment", "from border")
- max_features=500: Top 500 most important features
- sublinear_tf=True: TF ke log use karta hai (very frequent words ko dampen karta hai)

TRAINING:
- Input: 600 social media posts ka TF-IDF matrix (600 × 500)
- Labels: ai_sentiment_flag (Neutral, Suspicious, Threatening, Coded/Ambiguous)
- Random Forest 100 trees

RESULT: 42.2% Accuracy
(Ye LOW hai kyunki text data bahut diverse hai aur 600 posts kam hain.
 Real production mein BERT/GPT jaisa model use hoga.)

KEYWORD TRIGGER DETECTION (Rule-Based Enhancement):
AI model ke saath, hum ye keywords bhi check karte hain:
"shipment", "border", "package", "delivered", "naka", "police", 
"lay low", "hot", "usual spot", "payment cleared", "big deal"

Agar ye keywords text mein milte hain → Extra alert flag lagta hai.

PART 12: INTERVIEW/VIVA READY QUESTIONS & ANSWERS
################################################################################

Q1: "Aapka project kya karta hai?"
A1: CrimeGraph AI ek AI-powered criminal network analysis system hai jo 
    multiple data sources (CDR, FIR, Social Media) ko combine karke criminal
    networks ko graph analytics se map karta hai, ML models se risk predict 
    karta hai, aur blockchain se digital evidence tamper-proof rakhta hai.

Q2: "Blockchain kyun use kiya? Database se kya fark hai?"
A2: Traditional database mein koi bhi admin record modify kar sakta hai —
    court mein evidence ki integrity prove karna mushkil hai. Blockchain mein 
    har record ka SHA-256 hash hai aur har block previous block se cryptographically
    linked hai. Agar ek character bhi change ho, hash mismatch se automatically 
    detect ho jayega. Isse evidence COURT-ADMISSIBLE ban jaata hai.

Q3: "Kingpin kaise identify karte ho?"
A3: Hum 5 graph metrics combine karte hain:
    - Betweenness Centrality (35%): Jo suspect sabse zyada shortest paths pe 
      baitha hai, wo information flow control karta hai
    - Eigenvector Centrality (35%): Jo powerful logon se connected hai
    - PageRank (15%): Google-style importance ranking
    - Degree (10%): Kitne connections hain
    - Prior Cases (5%): Criminal history
    In sab ka weighted combination = Kingpin Score (0-100)

Q4: "Risk prediction kaise hoti hai?"
A4: Random Forest Classifier 13 features pe trained hai — age, prior cases,
    FIR count, graph centrality metrics, CDR frequency, financial flags, aur
    social media threats. Model 100% training accuracy deta hai. Har prediction
    ke saath Explainable AI (XAI) batata hai ki KAUNSE features ne prediction
    drive kiya — toh officer ko BLACK BOX nahi, transparent reasoning milti hai.

Q5: "Link Prediction kya hai?"
A5: Ye predict karta hai ki kya do suspects jo ABHI directly connected nahi hain,
    actually secretly connected ho sakte hain. Hum graph topology features use
    karte hain — Common Neighbors, Jaccard Coefficient, Adamic-Adar Index, aur
    attribute similarity (same gang, city, crime type). 90.2% accuracy mili.

Q6: "NLP model ki accuracy 42% kyun hai?"
A6: NLP model TF-IDF + Random Forest pe based hai jo relatively simple approach 
    hai text classification ke liye. 600 posts diverse text data hai with 4 classes.
    Production mein BERT ya GPT fine-tuned model use karenge jo 85%+ accuracy de 
    sakta hai. Abhi ke liye supplementary keyword-based detection bhi lagaya hai.

Q7: "Smart Contract kya hai yahan?"
A7: Hamara blockchain ek role-based access control enforce karta hai — 
    Investigating Officer sirf FIR/Seizure Memo register kar sakta hai,
    Cyber Cell sirf CDR/Social Media evidence, Forensic Expert sirf Lab Reports,
    aur Magistrate sirf Court Orders. Ye "Smart Contract" unauthorized access
    prevent karta hai aur audit trail maintain karta hai.

Q8: "Community Detection kaise kaam karta hai?"
A8: Louvain Algorithm use karte hain jo network ko modules/communities mein
    todta hai. Ye MODULARITY maximize karta hai — matlab same community ke
    andar zyada connections honi chahiye aur different communities ke beech kam.
    Isse hidden sub-gangs identify hote hain jo official gang affiliation se
    different ho sakte hain.

Q9: "Scalability kaise handle karoge?"
A9: Current system 150 suspects pe demo hai. Scale karne ke liye:
    - Neo4j graph database use karenge (millions of nodes handle kar sakta hai)
    - Apache Kafka se real-time CDR streaming
    - Hyperledger Fabric for production blockchain
    - GPU-based deep learning models
    - Microservices architecture with Docker/Kubernetes

Q10: "Kya ye real police data pe kaam karega?"
A10: Architecture design kiya hai CCTNS (Crime and Criminal Tracking Network) 
     ke compatible. Real deployment mein:
     - CCTNS API se FIR data feed hoga
     - Telecom operators ke CDR APIs se call data
     - Social media APIs (Twitter, Telegram) se OSINT
     - Banks ke STR (Suspicious Transaction Reports) se financial data
     Data format same rahega, sirf data source change hoga.
